Blurb privacy policy

Updated September 23, 2026. This page describes the current beta; earlier releases may have different reporting controls and defaults. Blurb is developed by Ali H. This policy describes the Android app with package name com.notifsummarizer.app.

Notification access

With your permission, Blurb reads notification message text, sender labels, conversation titles, timestamps and source app information, including while the app is closed. Android grants notification access broadly. Blurb filters incoming notifications to apps you select and uses supported message notifications to create summaries. It does not request access to your SMS database or address book. Notification contact images and original tap actions are used locally to display summaries and open the source conversation.

On-device summaries

The downloaded Gemma model processes message text on your phone. With cloud fallback off, Blurb does not upload message text for summarization. With cloud fallback on, an unsuccessful local attempt can send that text to the selected cloud provider or custom server. Settings shows the active mode and fallback preference.

Cloud summaries and tests

When you choose cloud mode, enable cloud fallback, or run a cloud test, Blurb sends the prompt, message text and sender labels directly to your selected provider (Gemini, OpenAI or Anthropic) or custom server over HTTPS, authenticated with that provider-specific API key when required. Blurb does not route these requests through a developer-operated server. A custom server receives message text even if it runs on your local network; it is not on-device processing. Provider retention, use and deletion policies vary. Review your selected provider or server operator before using private messages. See https://openai.com/enterprise-privacy/ and https://privacy.claude.com/ for the additional built-in providers.

For Gemini, Google processes these requests under its Gemini API terms and privacy policy. Treatment depends on billing status and region. Unpaid services may use inputs and outputs to improve products and may involve human review; their terms restrict submission of personal, sensitive or confidential information. For private messages, use local mode with cloud fallback off, or a billing-enabled Gemini project consistent with Google's terms. Paid services do not use prompts and responses to improve products under the current terms, but may retain them for abuse prevention and legal requirements. Blurb cannot verify billing status or delete data already processed by Google. See https://ai.google.dev/gemini-api/terms and https://policies.google.com/privacy.

Optional redaction

Redaction replaces detected identifiers on the phone before cloud upload. Detection is incomplete: names, addresses and other sensitive details can remain. If address classification is unavailable, available pattern redaction still runs and cloud upload can continue. Redaction is not a guarantee of anonymity. Local inference receives the original text.

Data stored on your phone

Your API key and preferences are encrypted in app-private settings using Android Keystore-backed encryption. Blurb keeps up to 200 summary and error entries in local history; that history is not separately encrypted. Raw messages and sender information may be retained in encrypted recovery records and Android notification extras so unread summaries can merge follow-ups and recover from interruptions. Recovery data is pruned as conversations are dismissed and during listener recovery cleanup. Clearing history alone does not clear active notifications or their recovery records.

The app list is queried locally to build the monitored-app picker; Blurb does not upload that inventory. Selected model files are stored in the app's external files directory. Downloads contact Hugging Face and its delivery providers; those services receive normal connection information such as an IP address, but Blurb does not send message content with model downloads. Opening external links is handled by your browser and the destination's own policies.

Optional usage diagnostics

Share usage diagnostics is separate from session replays. In builds with reporting configured, diagnostics start on for new installations. Saved choices are preserved across updates; an upgrade without a saved choice starts off. This control is not part of setup. Turn it off at any time in Settings → Privacy; doing so does not change replay consent.

While diagnostics are on, Blurb sends setup and download outcomes, engine success/failure categories and duration ranges, provider and structured failure codes, reasons notifications were skipped, listener disconnections, app version and source revision, Android API version, device manufacturer and model, and sanitized Java crash details to Sentry. Crash details include exception class and Blurb code frames, not exception messages or file paths. Reports exclude messages, summaries, sender names, conversation identifiers, API keys and app lists.

Reports contain a random installation identifier generated by Blurb, not a hardware or advertising identifier. It allows affected installations to be counted and is deleted whenever the diagnostics setting changes. Foreground session reports include a random session identifier, start/end times, duration and exit/crash status to measure reliability. Each diagnostic event has a random event identifier; events during an active, consented replay may also include its replay identifier. Blurb does not include your IP address in these payloads, but Sentry receives the connection address. These reports are not anonymous.

The local diagnostics queue holds at most 50 unsent events and session reports combined. Entries older than seven days are discarded when the queue is next processed; they can remain on disk until then. Delivery retries on later activity; turning diagnostics off deletes pending diagnostic events and session reports, resets the installation identifier and stops new diagnostic reports. Your choice is kept across updates. A request already sent cannot be recalled. Crash reports may be sent on the next launch. Server retention and deletion follow the developer's Sentry project settings and Sentry's policy at https://sentry.io/privacy/. Contact the developer for questions about reports already received; the random installation identifier is not tied to a Blurb account, so it may not be possible to associate a report with a particular person. This setting is separate from where message summaries are processed: local summaries can coexist with enabled diagnostics.

Optional session replays

Share masked session replays is an independent control, off until you enable it. It is offered during setup and in Settings → Privacy. Usage diagnostics never enable replay. If you enable replay, the Sentry Android SDK records your activity inside Blurb while it is in the foreground and sends masked visual recordings, tap positions, timing, replay identifiers and app/SDK metadata to Sentry. All text and images, including static UI labels, are masked during replay drawing; masking may not cover future custom drawing, so it is not a guarantee of anonymity. Other apps and the notification shade are not recorded. Sentry receives your connection IP address. This consent covers masked recordings only. It is separate from usage diagnostics and cloud/local message processing.

Replay uses a separate temporary SDK cache and can increase data, storage and battery use. Turning replay off stops recording, blocks new uploads and removes pending replay files. Already uploaded or in-flight recordings cannot be recalled. Uploaded replay retention and deletion follow the developer's Sentry project settings and https://sentry.io/privacy/. The 50-event and seven-day diagnostics queue limits do not apply to replay recordings.

Blurb contains no advertising and does not create a Blurb account. Its optional replay feature uses the Sentry SDK. Android, Google Play, cloud providers and download providers may independently process operational data under their own policies. The separate local summary/error history can contain sensitive information; inspect it before sharing a bug report.

Google Play purchases

Google Messages summaries are free. Other supported apps share 10 successfully displayed preview summaries per installation. Blurb stores the preview count and confirmed Pro ownership in encrypted app-private settings. Clearing app data or reinstalling may reset the preview; paid access can be restored using the Google Play account that purchased it.

The optional one-time Blurb Pro unlock is processed by Google Play. Blurb receives product and purchase state, a purchase token and signed purchase data to verify, acknowledge and restore access. Google handles payment details; Blurb does not receive payment-card information or send purchase payloads to a developer-operated server or usage diagnostics. Purchase checks can occur when you open Blurb, including in on-device mode. Google processes purchase, account and operational information under its privacy policy. Cloud provider charges are separate from Pro.

Setup and background activity

Blurb stores whether the one-time fallback suggestion has been shown. It does not enable fallback or download a model automatically. Blurb checks Android background battery restrictions locally to show a settings shortcut. Original-message expansion is off by default unless you have saved a different preference; message text is still processed and retained locally as described above.

Remote configuration

Blurb checks Firebase Remote Config while the app is open to retrieve recommended model names and optional update notices. Firebase processes an installation identifier and app/connection metadata, including your IP address. Blurb does not send notification text, prompts, API keys or summary history in these checks. Configuration checks are separate from optional Sentry diagnostics and can occur in on-device mode. Firebase Analytics is not included. See https://firebase.google.com/support/privacy for Firebase data handling. Manually selected models stay pinned; remote configuration cannot enable cloud fallback, change endpoints or turn on diagnostics.

Your controls and deletion

Turn Blurb off to stop new summarization, remove apps from the monitored list, or revoke notification access in Android Settings. Clear saved summaries with History > Clear history. Dismiss active summary notifications to clear their tracked conversation recovery data. Delete downloaded models in Settings. To remove the app's stored settings, key, history and remaining recovery data, use Android's app storage controls or uninstall Blurb; model files can also be removed separately. Blurb disables Android app backup. Local deletion does not retract requests already sent to your cloud provider or custom server.
