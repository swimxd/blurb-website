Get started

  1. Open Blurb and follow setup. If you skip, return to Settings to finish.
  2. Grant notification access in the Android settings page, then return to Blurb. Also allow Blurb to post notifications.
  3. Choose cloud or on-device summaries. Validate your cloud key with the sample, or download a local model. Setup can continue during the download; local summaries need the completed model.
  4. Select the messaging apps you want to monitor. Google Messages is the initial selection.
  5. Enable summaries and check the home screen for any permission or setup reminders.

Normal app updates preserve your saved settings. You can replay setup from About.

Choose where summaries happen

On your phone

A downloaded Gemma model works offline. E2B uses less storage and memory; E4B is larger. Blurb checks availability and shows download progress. Local processing can use more memory and battery, and quality may differ from cloud summaries.

In the cloud

Choose Gemini, OpenAI or Anthropic and enter your own provider API key. Message text is sent to that provider. A custom HTTPS endpoint is also supported if you have a compatible server. Review your provider’s privacy terms and billing before use.

Where available, Use recommended model follows Blurb’s curated recommendations. Turn it off to choose a model yourself. Previously saved manual choices stay pinned.

Fallback

Settings → Processing can let one engine take over if the other fails. Cloud-to-device fallback needs a downloaded model. Device-to-cloud fallback sends text to your selected cloud provider.

To keep message text on your phone, choose on-device mode and leave cloud fallback off. Downloads and configuration checks can still use the internet.

When does a summary appear?

Minimum length · recommended 300 characters
The first summary waits for enough accumulated new text in that conversation. Each individual message does not need to reach the threshold.
Wait for silence · recommended 20 seconds
Each new message restarts this timer. Shorter waits give faster updates; longer waits let more of the conversation arrive first.
Limit the wait · optional
Start summarizing even during continuous messages. The first-summary length threshold still applies. Model loading and generation take additional time.

If a summary is unread, even a short follow-up can update it after the wait. Blurb combines the previous and new text into one summary.

Restore recommended defaults resets timing and the prompt while keeping keys, models, selected apps and privacy choices.

Read and personalize summaries

Tap a summary to open the original conversation. Expand it to read original messages when that option is enabled. Pending messages still appear when this option is off. Long expanded text may be shortened; open the conversation to read everything. Layout and bold text vary between phone brands.

New messages may be folded into an unread summary with a pending status while Blurb works. History shows saved summaries and errors.

Advanced settings let you change the summary prompt, the small symbol before each summary, and whether originals appear when expanded. Keep {{messages}} in a custom prompt to mark where the conversation belongs.

Which apps work?

Blurb needs message-style notifications with readable content. The picker contains Google Messages, Signal, Discord and Microsoft Teams, even before installation. Not every notification from these apps has a supported format.

  • Google Messages: supported message notifications are the main use case. Recognized MMS processing notices are held while real content downloads.
  • Signal: set notification privacy to show names and message content.
  • Discord and Microsoft Teams: supported when they provide message-style notifications with readable content.
  • Other apps, including WhatsApp, Telegram, Messenger and Slack: not currently supported. Older saved selections for unsupported apps are ignored.

Image-message summarization is not currently supported.

Troubleshooting

No summaries appear

Follow any recovery action on the home screen. Check that summaries are enabled, notification access is granted, Blurb can post notifications, and the source app is selected. Its notifications must contain readable message content. Short conversations may still be below the minimum length.

Android hid some notification text

Android can replace sensitive notification text with a hidden-content notice, including when it detects a verification code. Blurb skips that hidden text rather than summarizing the notice. The home screen can show Android hid some notification text; choose View log for details. Blurb cannot recover text Android withheld. Open the original conversation to read it.

Summaries take too long

Check Wait for silence. Continuous messages restart it; Limit the wait can help. Loading a local model or retrying a busy cloud provider adds time after the timer.

A cloud request fails

Check the connection, provider, model and key. Read the error in History. On-device fallback can help during provider outages if you have a model downloaded.

The local model will not run

Check that the download is complete and the phone has enough storage and available memory. Try the smaller E2B model. If GPU processing fails, try CPU under model options.

Test with fictional messages

Open Settings → Test a summary and choose an example. Send test checks the engine; Post test notification also checks notification access and timing. Use a sample long enough to meet your threshold.

The launcher icon has not changed

Launchers may cache icons. Give it a moment; you may need to remove and re-add the home-screen shortcut.

Still stuck? Report a bug with the app version, phone, Android version and a fictional example. Reports are public: omit private messages, keys and sensitive screenshots.

Your privacy choices

Redact before upload tries to remove identifiers on your phone before cloud requests. It can miss sensitive details and does not guarantee anonymity.

Settings → Privacy has two independent controls. Share usage diagnostics starts on for new installations in configured builds. Existing choices are preserved across updates; an upgrade without a saved choice starts off. Reports include reliability information, device manufacturer/model, a random installation identifier and foreground session information, but not message text or summaries. You can turn it off at any time.

Share masked session replays stays off until enabled. It is offered during setup and records activity inside Blurb with all text and images masked, including static labels. Neither switch enables the other, and both are separate from cloud or local summaries.

History is stored locally and can be cleared. Read the privacy policy for details about storage, cloud providers, diagnostics, downloads and configuration checks.
